# Load test (2026-10-15)

Verified (run 2026-10-15, AMD Ryzen 7 5800X (8 cores, 16 threads), 32 GB RAM, Windows 11 Pro).

Measured on this machine with the settings below. This is not a claim about production capacity or about any other hardware.

## Settings

- Hardware: AMD Ryzen 7 5800X (8 cores, 16 threads), 32 GB RAM, Windows 11 Pro (16 logical CPUs); Windows-10-10.0.26200-SP0
- Software: Python 3.11.9, scikit-learn 1.9.1
- Started (UTC): 2026-10-15T23:10:13Z
- Server: uvicorn --factory mlserving.app:create_app --no-access-log, 127.0.0.1
- App config: MLS_RATE_LIMIT_PER_MINUTE=0 (limiter off), auth off, request log off, JSON access log on (stdout discarded), MLS_PREDICT_THREADS=1 (default)
- Model: v2 (production)
- Client: aiohttp, 4 client processes on the same machine, keep-alive connections, closed loop (no think time)
- Payloads: 500 pre-serialised bodies drawn from N(mean, std) clipped to the training range, seed 0
- Each repetition runs 15.0 s after a 4.0 s warm-up; 3 repetitions per cell; batch size 32.

## Command

```
python loadtest/run_loadtest.py --workers 1 4 --concurrency 16 64 --duration 15 --reps 3 --wait-quiet 50 --wait-budget 240 --hardware "AMD Ryzen 7 5800X (8 cores, 16 threads), 32 GB RAM, Windows 11 Pro"
```

## Notes

Model v2 (100 boosting iterations) was in production. One TimeoutError (client timeout of 30 s) occurred across all 24 repetitions of 15 s; request counts per cell are in the JSON. An earlier full run of the same command (same day; its printed summary showed 15 and 18 errors in the two 4-worker, 64-connection cells, kinds not recorded; the results file was lost when the script crashed while stopping the server) is not reported; the harness now records error kinds and saves after every cell.

## Caveats

- **Shared machine.** System-wide CPU use measured during the repetitions peaked at 100% (it includes the load test itself); other jobs on the machine kept it saturated before every cell as well (`background_cpu_percent_before` in the JSON), and waiting for a quiet period was not possible. Absolute numbers are therefore lower and noisier than an idle machine would give, and the gain from 1 to 4 workers is understated.
- Client and server run on the same machine and compete for CPU.
- The load is closed loop: each connection waits for its reply before sending the next request, so latency reflects saturation at that concurrency, not a fixed arrival rate.
- Windows event loop (no uvloop); numbers on Linux will differ.
- `Errors` counts requests that failed or returned a non-200 status; they are excluded from latency and throughput.
