# Training runs (2026-10-15)

Verified (run 2026-10-15, AMD Ryzen 7 5800X, 32 GB RAM, Windows 11 Pro, Python 3.11.9, scikit-learn 1.9.1, seed 42).

California Housing (20,640 block groups, downloaded at run time; scikit-learn verifies the archive's SHA-256) split 80/20 with `train_test_split(random_state=42)`: 16,512 training rows, 4,128 held-out rows. No hyperparameter search was run. Each run took about 10 seconds on CPU.

## Commands

```
python -m mlserving train --out models --version v1 --max-iter 300
python -m mlserving train --out models --version v2
python -m mlserving promote v2 --model-dir models
```

v1 was promoted first and v2 replaced it after a development load-test dry run (not committed) and the micro-benchmark in `2026-10-15-predict-latency.md` showed `model.predict` dominating request time; v1 is kept as `archived`. The choice of 100 iterations (the scikit-learn default) was made for latency, not from the test metrics. Retraining v1 and v2 a second time gave identical metrics (same seed, same library versions).

The interval is a 1,000-resample bootstrap over the 4,128 test rows. It does not include variation from the split or the seed; a single seeded split was run because the model is not the point of this repository. v1 fits the training data more closely (train RMSE 0.3055 vs 0.3971) and scores a lower test RMSE than v2; the two intervals overlap only partly.

## Artifacts

Each version folder holds `model.joblib` (v1 468,140 bytes; v2 167,689 bytes), `metadata.json` (schema, feature order, metrics, git commit, training date, library versions, SHA-256 of each artifact) and `reference.json` (a 1,001-point quantile sketch of each training feature, used by the drift module; no dataset rows are stored). Each run also logged its parameters, metrics and the artifact folder to an MLflow local file store (`mlruns/`, not committed).
